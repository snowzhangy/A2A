# Live quality experiments, 27 October 2026

Two changes are adopted: direct Qwen voice conditioning without a throwaway synthesized
sentence for each profile, and a clause-safety fix that keeps the Mandarin compound
`只不过` together. The app continues to use streaming Qwen. Lower-step OmniVoice and
adaptive buffering remain explicit experiments. Dub-quality live playback is not achieved.

## Qwen voice preparation

The pinned mlx-audio adapter's input preparation helpers fill the same reference codec,
text and speaker caches without generating audio. Global warmup still compiles generation;
the first real units learn per-voice level and duration. The first unit uses bounded gain
instead of a throwaway sentence's loudness estimate. This relies on private APIs of the
currently pinned dependency and must be rechecked when that dependency changes.

Four matched lines across three actors used identical directed text and reference clips,
reset generation seeds, and alternating preparation order in one process. Direct
conditioning took 0.010–0.199 seconds; the old preparation took 2.187–3.423 seconds.
Both methods share process caches, so these are development timings rather than an
independent cold-start benchmark. The two cold-first conditioning cases took 0.096
and 0.199 seconds. Generated durations matched for all four pairs and post-shaping
waveform correlations exceeded 0.9999998. This supports removing redundant computation;
it does not establish identity qualification or improved perceptual voice quality.

Private evidence: `.local/live-dub-lab/qwen-prepare-01/`. The four references and
directed text are assisted inputs; these isolated samples do not measure live ASR/MT.

## OmniVoice decoding steps

The [upstream generation API](https://github.com/k2-fsa/OmniVoice/blob/master/omnivoice/cli/infer.py)
exposes the step count and defaults to 32. Matched 32/16/8-step samples were generated
with the same text, reference and seed. A concurrent GPU separation job was present.
Median first audio was 10.13 / 5.10 / 2.70 seconds. At 8 steps, Apple's local
back-transcript had one word error across the four samples; 32 steps had four and
16 steps had one. The short acknowledgment is especially sensitive to ASR errors.
These counts cannot measure acting, expressiveness, artifacts or voice identity.

The 8-step worker also ran through actual Apple ASR/MT and automatic voice acquisition.
It completed 8/13 commits at 7.20 seconds median source-onset delay. Faster isolated
inference has not made this a successful live replacement. Product OmniVoice stays at
32 steps. Use the lab worker explicitly to reproduce the lower-step experiment.

Private evidence: `.local/live-dub-lab/omni-steps-01/` and `omni8-live-01/`.

## Playback under load

A concurrent, independently launched GPU experiment caused substantial contention.
It was left running. The following sequential runs use the same 37-second scene and
6-second debt / 8-second source-lag limits; load changed between them. CPU build/check
work also ran during some of these experiments. The table describes individual runs
and is not a controlled causal comparison.

| Run | Commits completed | Completed committed-source coverage | Median onset delay | Underruns |
| --- | ---: | ---: | ---: | ---: |
| Qwen, fixed clause policy | 0/13 | 0.0% | 6.30 s | 7 |
| Qwen, adaptive buffering | 4/13 | 33.1% | 9.42 s | 0 |
| Qwen, direct conditioning + adaptive buffering | 9/13 | 70.1% | 4.54 s | 1 |
| OmniVoice 8 steps | 8/13 | 65.7% | 7.20 s | 0 |

The first run started seven phrases but completed none: starvation triggered recovery
and abandoned them. `research/run_metrics.py` now reports completed count and completed
coverage separately from playback starts. Both cover committed spans, not all speech,
and neither establishes semantic accuracy. Median delay considers starts, so it can
look better when later phrases are cut off. The diagnostic has a regression test for
interrupted playback.

`--adaptive-prebuffer` asks the pure reducer to observe at least two PCM chunks and
reserve audio for a generation rate below real time. Completed short phrases bypass
the reserve. Initial handoff and later phrases use the same decision. It made phrases
finish in one overloaded replay but substantially increased delay and skipping, so
the app does not enable it by default. Its source/text duration estimate is imperfect;
it cannot guarantee uninterrupted playback or make an overloaded GPU fast enough.

## Artifacts and scope

All runs are file-paced through the real pipeline. They use no process tap or output
device. Actors are still merged: two tracker identities for three annotated actors.
The actor-profile database from the prior experiment is retained, with no new claim
of cross-episode recognition. No new checkpoint, model training, or external inference
service was introduced.

`qwen-conditioned-01/preview-timeline.mp4` and `omni8-live-01/preview-timeline.mp4` use the reference
video's picture and the actual translated output. They contain no original soundtrack
or added background. The last video frame is extended so late translated speech is
retained instead of being cut at 37 seconds. These are listening artifacts, not proof
of dub-quality output.

Earlier exports named `preview.mp4` and the prior queue comparison MP4s used the compact
`--translated-out` speech stem, which omits empty-bus time. They are unsuitable for
judging live timing. The corrected exporter uses `--out`, retaining actual silence and
delay; the corrected Qwen and OmniVoice previews are 43.32 and 42.24 seconds long.

Runnable checks: `scripts/check.sh`, `scripts/build_app.sh`, `scripts/smoke_app.sh`, and
`python3 -m unittest discover -s research/live_dub_lab -p 'test_*.py' -v`.
All passed: 176 Swift tests executed (two interactive tests skipped), 83 harness tests,
five lab tests, SDK and manifest checks, optimized app build and synthetic app smoke.
Logs remain in `.local/live-dub-lab/`. The main unresolved quality work is reliable
speaker/turn attribution, ASR names and word errors, context-aware concise translation,
and voice-free background restoration.
